Two defects, both in the spend path:
  1. **No transient/terminal classification.** `generation/jobs.py:409` catches every `_hf.HiggsError` and calls `fail()`, so a 503 and a rejected prompt land identically. `code = getattr(e, "code", 500)` at `:410` is **dead code**: `generation/higgsfield.py` raises `HiggsError` as a bare string (`:70`, `:72`, `:82`), so nothing ever branches on it. Fix: give `HiggsError` a `.code` parsed from the CLI message (default 502); wrap `hf.wait` in a bounded retry (3 tries, backoff — a 503 on one poll is usually one poll); then in the `except`, when `e.code in (408, 425, 429, 500, 502, 503, 504)` **and** `external_task_id` exists, write **`TIMEOUT`** instead of `FAILED`. `resume()` (`:213`) already returns a ticketed `TIMEOUT` to `CLAIMED` on the **same** provider job, so recovery needs no new machinery. Terminal stays only for `higgsfield.py:154` (the job ended without a result).
     - **and fix `_inflight` in the same change** (`jobs.py:293-301`): it counts **only `CLAIMED`**, so a `TIMEOUT` job drops out of the daily cap while Higgsfield is still rendering it and will still charge. Its own docstring already promises the right thing — *"credits of the provider jobs that are created but not finished"* — so this is the code under-implementing its contract: count `("CLAIMED", "TIMEOUT")` **when `external_task_id` exists**. Without this, fix (1) alone would let three concurrent transient failures quietly overrun the cap (review-prompt C4/C5's "a spend the daily cap does not see").
  2. **No job-level recovery in the UI** — the twin of rule 10's "Use it anyway": a stalled job shows a red error with nothing to click. Four actions, cheapest first, each explicit so nothing double-pays by accident:
     - **Refresh** — re-read local state, reconnect SSE. No provider call.
     - **Check** — one read-only `higgsfield generate get <external_task_id>`. **Spends nothing.** If it says `completed` and no file is held, download `result_url` (`higgsfield.py:159`, a plain HTTPS GET, no auth) and attach by ticket (`mirsal job done J048 --file … --model … --cost …`). **This alone recovers J048 for free.**
     - **Continue** — `jobs.resume(out, jid)`: back to `CLAIMED` on the same ticket, wait again. Cannot double-charge.
     - **Retry** — request again from scratch, **spends**; a separate labelled action, never the default.

     A ticket that says `FAILED`/`TIMEOUT` while the provider says `completed` is a **divergence, not a failure**: say so in those words, offer the four actions, and write the reconciliation as a `history` line (actor human).

## 5. Quirks that cost time

- **Most "it still fails" reports were a stale server process** (Python loads code once). Compare the process start time with the file times first.
- VP9 (`row-mt`) output is not byte-stable: compare metrics, never WebM hashes. Windows `os.replace` fails with WinError 5 on an open file (and a reader can get `PermissionError` for an instant): write through `runtime/atomic.py`, read through `atomic.read_text`; never a fixed `<name>.tmp`.
- **Never put a regex or a Windows path (`\b`, `\d`, `\1`, `\t`, `\a`) in a Python string written through a shell heredoc**: the backslash sequence becomes a control character (a backspace, chr(1), a tab) and silently breaks the pattern or the test (`grep -rlP "\x08"` finds such damage). Write scripts and tests with the Write / Edit tools and use raw strings (`r"..."`) or `chr(92)`; PowerShell has no `&&` and mangles non-ASCII when it rewrites files. A heredoc that contains an apostrophe can also fail to parse in the Bash tool: use the Write tool for the file.
- Two scripts of the Studio must not declare the same top-level `const` (the second one is not run at all; `history.js` was dead for a while because of `ago`). They also share ONE `ACT` object: a second `ACT.name =` in a later script silently replaces the first (`history.js` replaced `hopen`, so "Earlier batches" opened batch NaN); `tests/test_js.py` fails on any such clash that is not listed as intentional, and on a `data-act` button nothing handles. Class names in `agent.css` are namespaced (`ag-`, `is-`, `k-`) because the Studio's own CSS already uses `.step`, `.tile`, `.sel`, `.done`.
- LM Studio loads a listed model on first use (the first call is slow); `qwen3.5-4b:2` is an instance suffix that exists only while a second copy is loaded (use `qwen3.5-4b`); Qwen thinks unless the closed think block is prefilled (the client does). A test must never reach the real Higgsfield CLI (`MIRSAL_NO_REAL_CLI` is set by `tests/__init__.py`).
- For browser checks: run your own server on a spare port against a **copy** of `out/` (`MIRSAL_OUT=<copy>`, never press Create) and drive it with Playwright; the browser caches `studio.css`, so reload after a CSS change. After a selection click the pack grid re-renders, so re-query elements instead of keeping references. Playwright's `goto` to the same URL with only a hash does NOT reload the page (it keeps the old server's data): use `location.reload()` after restarting your test server. A move of files needs the import paths in STRINGS fixed too (`mock.patch("mirsal.services.telegram._ssl_context")`, a `python -c` snippet): an AST pass cannot see them.
- The Edit tool fails on a **multi-line** match in a CRLF file (`tests/test_live.py` is CRLF: `git ls-files --eol`) but works for a single line: patch such files with a small script written by the Write tool (it sets `newline=""` and re-joins with `\r\n`), never with a PowerShell heredoc.
- `python -m unittest discover -s tests -t .` takes about 5 minutes and prints a lot; to see only the verdict, pipe it through `Select-String -Pattern "^(FAIL|ERROR): |^Ran |^OK|^FAILED"` (and do not interrupt it mid-run: a killed run leaves no verdict).
- **A `# comment` after a value in `mirsal/.env` used to become part of the value** (the chat's provider was `"auto   # the chat assistant;..."`): fixed by one parser, `runtime/envfile.py`; the suite pins `MIRSAL_DB_WRITE=0` and `MIRSAL_TRACE=none` because the real `.env` sets them (a test must never write to the real Postgres or post to the real LangSmith project).
- ~~Python 3.11 in `mirsal/.venv`~~ superseded: the venv is `mirsal/venv` on the macOS checkout, Python 3.14. In a bash heredoc, an apostrophe or `\\1` / `\\n` inside a Python string is mangled: write edit scripts with the Write tool and raw strings, run them afterwards.
- Any bot token pasted into a chat is compromised and must be revoked after testing. `mirsal/.env` and `out/telegram.json` are git-ignored.
- **To try the resolver without the server**, run it directly: `cd mirsal && venv/bin/python -c "from mirsal.agent import resolver as R; print(R.classify('make him wear winter coat', False, True, False)); print(R.resolve('make him wear winter coat', {...}))"`. Importing `mirsal.agent` pulls in `cv2` and the whole pipeline, so the venv is required.
