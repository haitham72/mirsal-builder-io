# "Use it anyway" — every judgement-call block can be allowed, on every surface (2026-10-03)

<sub>Part of [engine-and-studio.md](../engine-and-studio.md).</sub>

**Rule 10's standing rule:** a rejected picture is never a dead end and never a bare word. Where a rejected picture is shown, the person sees the picture, one sentence of plain-words reason, and the override on that picture. A rejection with no picture and no override is a bug.

**Every surface that shows a rejected picture must carry the override:**

| surface | what it must show | state |
|---|---|---|
| the Studio tile (`studio-tiles.js` `tileHtml` / `blockedBox`) | the picture (or the still's plain cell), the reason, `Use it anyway` / `Take it back`; a blocked animation whose WEBM still exists keeps that clip dimmed with the reason over it | built |
| **a slice of the left image sheet** — the sheet SVG itself, not only the cut tiles | the cell's rect is a full-cell hit area; hovering shows the reason and what the click does; the click is the ONE cell control (below) | built; it never opens a tile |
| the chat's card (`chat-cards.js` `tileHTML`, `runHTML`) | the picture, the reason, the override, read from the card's own `allow` block (`gates.allow_info`) | built |
| the batch's bulk control | **one** `Use all anyway (N)` / `Take all back (N)` over whatever is allow-able now | built, per kind (stills, animations and video sheets) |

**The sheet is a first-class surface.** The left sheet (`cutSvg`) already draws the cell rectangles, the cut lines, the index numbers and the issue marks, so it can be the cheapest place to allow: a rejected cell must be clickable exactly like its tile, with the same hover, tooltip and `aria` treatment. Not a new panel — the same control on the picture that is already there. `pointer-events` on the mark, a hit area the size of the cell, and the click routed to the same `POST /api/generations/{id}/allow` the tile uses.

**One bulk control per batch, per kind.** `allowAllRow` (`studio-tiles.js`) covers stills and animations; `SR.bulk` covers video sheets. Each control counts what is allow-able *now* ("Use all anyway (3)"), never everything. The chat's creator card carries the same pair for all three kinds.

**The AI/vision verdict never removes a picture.** `docs/agent-and-chat.md` (the creator) and the judge: a sticker the vision model would reject is shown, with the reasons, and `Continue with them` / `Continue without them` — it never deletes and never hides. When the judge cannot run at all, the run says so in words rather than silently treating everything as approved.



### The engine side (built 2026-10-03)

Haitham: "any rejected image/video must give me an option to allow it". `engine/verify.py` holds the one table: `TECHNICAL` blocks (Telegram would reject the file: `dimensions`, `transparent_corners`, `static_file`, anim `size_budget`, `codec_vp9`, `dimensions`, `fps`, `duration`, `no_audio`, `alpha_mode_tag`, `alpha_decoded`, a crashed check) stay final, as does a cell with nothing cut; `OVERRIDABLE` lists the judgement calls: stills `blank_cell` (only when something was found), `foreground`, `inside_cell`, `no_spill`, `holes`; animations `inside_slot`, `cross_slot`, `loop_seam`; sheet-level cases already have "Cut it anyway". `POST /api/generations/{id}/allow {kind: still|animation, index | indexes | all, allow}` (202, free) stores `still_override` / `anim_override` on the sticker with a human history line (APPROVE "allowed anyway: ..."; taking it back writes REJECT); the check stays in the report as a WARN "(allowed by you)" and `metrics.waived`, using `verify.OVERRIDABLE` and `verify.waived()` rather than a second verdict path. Stills are re-cut from the stored sheet. For animations, the first switch renders only when the blocked pre-check produced no clip; once both verdicts are finished, `anim_finished` swaps the stored status/reason/metrics/report/WEBM immediately and every later allow/take-back does no decode or encode. A genuine re-cut/reslice deletes those remembered verdicts, so the next switch renders against the new pixels. `verify.run(inp["waive"])` keeps the permission through every later cut, `set_appearance`, reslice and re-animate, and G2 / G4 then approve normally. `GET /api/generations/{id}` carries `allow.{still, animation}` `{can, allowed, undo, why, final}`; the tiles in `studio-tiles.js` draw only what the server reports.

Animation verdict replay lives in `verify.animation_verdict`: it reads the stored checks and uses the same `_apply_waiver` as `verify.run`, with `OVERRIDABLE["animation"]` and `waived()` defining permission. A failed check remains `ok=False`; allowing it changes its severity to WARN and adds "(allowed by you)". Encoded clips that fail a final check are retained too; the first allow of an existing clip needs no render. Replay requires the complete report for that clip: a short slot pre-check report must not hide a later loop-seam failure. The remembered verdict includes the review state, so a prepared clip blocked by `inside_frame` stays blocked for review. A real re-cut marks the previous verdict stale and clears `anim_finished`; the next switch renders once before remembering the new pair. Every click still adds its own human history entry. The existing `/allow` body and response are unchanged.

G3 and returned-video judgement calls also use that catalogue: `OVERRIDABLE.video_sheet` contains `no_outline_on_sheet`, `video_specs`, and `layout_match`. `gates.allow_sheet` records reversible `sheet_override` permissions and human sheet/cell history; stored checks and every later `slice_video` use the verifier's existing waiver, retaining `ok:false` with WARN “allowed by you”. Decode failures, crashes and a sheet with the wrong approved slots stay final. Allowing a held video slices the same file without a new provider request. Taking permission back restores the sheet block and prevents G4/G5 approval until corrected or allowed again.

`sheet-recovery.js` draws the same reason, per-sheet decision and counted bulk pair on the Make a video dialog, Animation tab panel and full analysis, the video-sheet picture itself, and chat generation cards. The creator stops with the sheet picture in its attached generation card, a one-sentence reason, an explicit free sheet override and the bulk pair; its sheet action preserves A# ids rather than converting them into sticker numbers. `/allow` accepts `kind:video_sheet` with `sheet:A#`, string `indexes`, or `all`. `allow.video_sheet` is computed by `gates.allow_info`; screens do not classify checks themselves. Still and animation bulk controls and the chat tools also use that shared eligibility.
