# The Studio: the simple flow (`console/studio-*.js`; file responsibilities in `docs/architecture.md` §6)

<sub>Part of [engine-and-studio.md](../engine-and-studio.md).</sub>

**The page.** A request starts a *session*: **Batch 1**; **Create more** adds the next prepared sheet of the same subject on purpose; each batch has an include checkbox; **Animate** acts on every included batch. The header `Request > Prompt > Stickers > Animation > Pack` is the navigation and **every step is its own view** (`GS.tab`, `stepsHtml`, `gbodyHtml`; the same three are what the Studio shows for whichever batch it presents: a click on a batch in the *Earlier batches* column makes it the session (`ACT.hopen`), so an old batch is one click from being worked on again; the counts come from the one `gstats`):
- **Request**: the original request, editable; the outline choice; *Generate again* starts a new session (the old stickers stay in History).
- **Prompt**: the sheet and video prompts with Copy, template id/version, plan source, and every cell's prompt with its 1-5 tags (`planView`). The Studio screen shows no prompt preview under the box (removed 2026-10-03: the Prompt tab is the one place the prompts are read; `POST /api/plan` is unchanged).
- **Stickers**: always the **still** stickers, even after animation. Each batch has its green-screen sheet inline beside the tiles (`sheetPanel`: Raw / Keyed, measured cut lines, numbered cells, every sticker's boundary; *Full analysis* opens the dialog with the checks and thresholds), the **x** (drop from the set), and *Edit* in the sticker modal; an edited still is tagged "edited".
- **Animation**: the animated stickers only, in the same two-column layout as Stickers. The left column (`.gleft`, scrolls on its own) holds the **video sheet** (`videoPanel`) on top and, always, the **green screen** (`sheetPanel`: raw / keyed sheet, cut lines, chips, the animation box) below it, so the image-prepare side never disappears once the batch is a video (a test guards it). The video sheet is: the prepared video playing as one sheet with the same cut lines and numbers, an in-place **dashed, faded box in the colour of the problem** over every cell that is not in the set (a thin solid outline over one kept with a check; dashed + faded always means "will not be exported" and the item stays clickable; see "Issue colours"), a chip per cell (click to open it), and the analysis at a glance (source, out of bounds, no animation, size, work done this time and how many came from the cache); *Full analysis* (`animDlg`) lists every animation (frames, fps, KB, CRF, loop seam against its limit, pixels on the border and in how many frames, time) and every check that did not pass. Before animating it is an empty state with the Animate button; while encoding, live in-browser previews; an animation that leaves its cell is marked orange (dashed, faded), labelled *Out of bounds* with the frame number, kept to look at and **off by default**, with an *Include anyway* button (see "Issue colours" and `inside_frame` in the verifier).
- **Pack**: a three-step modal (`ACT.gadd`, `pwSync`, `ACT.pwgo`): 1 choose the pack (new with an editable name, or existing; when stills of the same stickers are already in it, *Replace the stills* or *Add next to them*), 2 how it looks on chat / light / dark / transparent / wallpaper, 3 the names that go into the library (name, emoji, and the generator's file name, read-only).
- **Edit in place.** The sticker modal's *Edit* opens the editor with `back = {gen, index}`: the button reads *Save to sticker* and posts the canvas to `POST /api/generations/<id>/edit {index, png}` (`pipeline.edit_still`): the still is replaced **in place** (same file, same `S#`), the original is kept once in `source/orig/S#.png`, the sticker gets `edited` and a human `EDIT` history line, appearance re-renders skip it, and the page returns to Generate (the editor's normal *Save* still saves into a pack). 409 while a job runs; an edited PNG over the size limit is refused.
- **Stale-server warning.** Python reads its code once at start, but the page is read from disk on every load, so a server started before an edit runs older code than the page it serves (new buttons answer "not found", fixes do not apply). `Console.stale()` compares the modified time of every `.py` file with the server's start time; `GET /api/generations` returns `stale`, and Generate shows a banner saying to restart the server.
- Background is a dropdown, a Size slider scales the tiles, and a step that has to wait for a running job waits quietly (`postWait`) instead of showing "busy".

The Generate screen is one panel: **type a request -> the stickers appear -> Animate -> Add**. Nothing else is needed for the common path, and the review gates are still decided and recorded, behind those clicks:

- **Generate sheet** (the paid step after *Generate prompt*, below; or Enter in the box, or a prepared-sheet chip) starts the run and counts as the human's **G1** decision (`reviews.plan.note = "approved by pressing Generate"`; an Inbox task keeps its own approval).
- The grid shows the stickers. The only per-sticker control is the small **x** (drop it from the set / bring it back): `POST /api/generations/<id>/drop {index, dropped}` is a human reject (or approve) at the stage the sticker is in (G2 before animation, G4 after), reopening an approved pack when needed. Blocked stickers (Python's block is final) show the reason and have no x.
- **Animate** (sheets with a prepared video) runs the live in-browser preview at once and encodes the real WEBMs; stickers that were dropped are skipped. **Make a video...** (sheets without one, such as the generic emojis) is the single multi-step path: `POST .../quick_sheet` approves the kept stills, builds the video sheet and approves it for sending; a dialog offers the download, the video prompt and the upload (attached to `A<n>`), and closes when the slots are sliced.
- **Add to pack** (`POST /api/generations/<id>/add {pack_id? | pack_name?}`) is G2 + G4 + G5 in one call: it approves what is still pending, approves the final pack (`pack_limits`), and adds the **animated** stickers when there are any, else the **stills**, to the Library pack (a new pack named after the subject unless the user types another name, or an existing one). Body: `{pack_id? | pack_name?, mode?: "replace" | "add", names?: {index: {name, emoji}}}`. When an animated sticker's still is already in the target pack, `mode: replace` puts the animated one in the still's place (position, cover) and deletes the still; `add` keeps both. `names` are what the user typed in the Pack wizard (default `{subject} {action}`, e.g. "Generic emojis laughing"); the generator's file name (`img-027-generic_emojis-generic_emojis_laughing`) is stored as the sticker's `file_name` and shown in Sticker details. Pressing Add twice adds nothing twice (`result.added`).
- One primary button per state: Generate -> Animate (or Add N to pack when there is no video) -> Add N to pack -> Open pack. The alternative is a quiet link ("or add the stills", "Make a video...").
- **The white outline is a choice**, per generation: On (12 px) or Off, next to the prompt (remembered in the browser). `outline_px` is stored on the result and used for the stills and for the animations; `0` makes the sticker equal to its plain cutout. The video sheet never has an outline (it is added once, after the video).
- **The edge finish = erosion + outline** (added with the merge work, `bf85e47`; **the UI half is not built yet** — today only the API and tests carry it): `erode_px` (0-8, `EngineConfig`) trims N px of key fringe from the alpha *before* the outline is drawn, which removes the dark key line the source art leaves at the edge; it is a separate choice from the outline (0-40). Both are chosen at create (`POST /api/generations {outline, erode}`) and can be changed later **without re-keying**: `POST /api/generations/<id>/appearance {outline?, erode?}` re-renders every still from `source/plain/S#.png` through `render.apply_edge()` (one exact alpha composite — the old path composited the subject over white *and* kept its alpha), re-runs only the finished-image checks (`verify.run(..., only=...)`), never overwrites a sticker Python BLOCKs, records an `appearance` history entry, and marks the batch's animations **`anim_status: "STALE"`** (with `review.anim = "NONE"`) so the next Animate re-renders the frames with the new edge. 409 while a job runs. The plain twin is always `outline_px=0, erode_px=0` (the video sheet is built from it).
- When nothing prepared matches a request the page offers **Get the Higgsfield prompt**: `POST /api/plan` (the template and slots, copyable sheet and video prompts) and `POST /api/tasks` (reserves the next `img-NNN-<subject>` / `vid-NNN-<subject>` names and writes `out/tasks/NNN.json`, the Phase 3 `tasks` row: `provider: higgsfield-manual`, `external_task_id` = the reserved folder, `name_key`, `request`, `plan`). `generation/tasks.py` also serves `GET /api/inbox` (every watch folder with its state, misnamed ones with the nearest valid name) and `POST /api/generations {task}` (a run linked to its task); the page does not need them for the common path.
- The detailed gate API (`review`, `video_sheet`, `.../video`, `regen`, `pack_add`) is unchanged and tested; the UI above is a thin layer over it.

**Generate prompt, before the sheet (2026-10-03).** The Studio's button is **Generate prompt**. It creates no batch and spends no Higgsfield credit: it calls `POST /api/plan` and opens a **pre-batch Prompt step** in the Studio. That step is the Prompt tab's own editor (`planView`, `copyBox`, `pdText`, `pdFoot`), fed by a browser-only draft (`GD` in the Studio feature scripts (`docs/architecture.md` §6), `number:'draft'`, saved in localStorage `mirsal.prompt-draft`, never a `G###`, never in `SES` / `GM`, and never in the Earlier-batches column or Remove). Edits live in `PD['draft:sheet'|'draft:video']` and survive re-renders and reloads. **Generate sheet** inside the step shows the Higgsfield price on its own line above the button and is the only click that spends (rule 13): it calls `liveStart('sheet', ...)` with `ai:false`, the draft's style, loop and refs, the text as `sheet_prompt` (sent when it differs from the template, and always when the AI enhancer wrote it) and the previewed plan as `plan` (its template, `expanded_by`, and `slots.cells` / `subject_description` / `key_colour`), so the enhancer is never asked a second time and the batch keeps exactly the cells, tags and emoji the person saw. The server treats `plan` as untrusted (`tasks.plan_from_preview`): it validates types, sizes and characters, re-lints the cells with the enhancer's rules (`expander.lint_slots`), and rebuilds the task, the template, the style and every prompt itself (`prompter.render_plan`), so the cells cannot carry instructions; an invalid plan is a 400 in words and spends nothing, a transformation request is rebuilt whole by its built-in template, and a custom `sheet_prompt` still overrides only the sheet text (`docs/api.md`). It stays disabled until a price is shown (a failed price offers "Retry the price"). A paid start consumes the draft; a refused start keeps it. Another batch taking the Studio hides the draft (`gdOn()`), the composer's **Prompt draft** button brings it back, and **Discard prompt** forgets it.

**The AI enhancer in that step (Haitham, 2026-10-03: "it should just work").** With the enhancer chip On, Generate prompt posts `POST /api/plan {ai:true}` (`gdPlan` in `studio-prompt.js`), which runs `generation/expander.expand` through `services/llm.complete()`, i.e. through the engine the person chose: Local (LM Studio, free), Cloud (one small OpenAI call) or Auto, and the local model of the drop-down. Nothing refuses: the line "Asking the AI enhancer (local · model)…" shows while a slow local model thinks, and the step then shows what the model wrote (header "written by the AI enhancer (model)"; the saved setting is not touched). When the model failed or there is no key, the server returns the built-in plan with `expand_error`, and the step shows it as the built-in prompt with a one-line notice in plain words (`gdNote`, `.gdnote.bad`); a transformation ("dog as banana") says the template wrote the cells and the enhancer was not asked. A written plan has a quiet **Use the built-in prompt instead** (`ACT.gpromptfree`: plans again with `ai:false`, the enhancer setting unchanged). Nothing in this step is blocked by the enhancer. **The engine control** sits under the composer bar while the enhancer is On (and while nothing can answer, so the way out is on screen): the AI screen's own Auto / Local / Cloud choice, the local-model drop-down and its one status line, plus "Local: free. Cloud: one small OpenAI call." It is the same code as the AI screen's gear panel (`chat-stage.js` `beRow` / `modelRow`, handed the Studio's source `GET /api/ai` through `AIENG.rows`; `docs/agent-and-chat.md`, Models). The chip is enabled whenever `GAI.configured` (`GET /api/ai`): any engine the choice allows can answer, so LM Studio alone is enough and no OpenAI key is needed; when neither can, it is disabled and its tooltip says which one is missing (`aiWhy`). With the Cloud engine the button's chip reads "1 AI call" instead of "free". **Enter in the box is unchanged** (`ACT.ggo`: a paid sheet at once, with no price on screen; it sends `ai:` the enhancer flag to the sheet route). Guarded by `tests/js/prompt_step.test.js` and `tests/js/enhancer_engine.test.js`.
