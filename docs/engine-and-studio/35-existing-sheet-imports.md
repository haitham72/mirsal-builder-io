# Existing-sheet imports

<sub>Part of [engine-and-studio.md](../engine-and-studio.md).</sub>

`flow/imports.py` owns the free import lifecycle. A validated sheet becomes a normal batch through `pipeline.start` and `run_stills`, with its own measured layout and ordinary review gates. A video named for a destination attaches only to its approved G3 sheet; a video imported on its own (Library > Packs > + > Import pack) is a batch of its own: its first frame is the sheet (`first_frame`), the video is the batch's prepared 3x3 video, `run_stills` then `run_animate` cut both, and the batch waits for review like any other (animations that leave their cell are soft-blocked until the person includes them). **Import inside a batch** (`import_file(batch=G###)`, `_into_batch`; the Studio's Import picture / Import video on a batch header): a picture becomes the batch's NEXT GENERATION, like Regenerate (the main generation's `prompts.json`: its cells, tags, emoji and `task_slug` naming; `parent` = the batch root, `regen_of` = the main; outline and trim kept). A video attaches to the batch's MAIN generation (stills must be cut, nothing being cut); `sheet_match` compares its first frame (48x48, mean absolute difference) with the image sheet and with every video sheet not removed, and the closest wins, with no question asked: the **image sheet** -> it becomes the generation's prepared 3x3 video (`source.video_path`; a sliced video sheet is retired with `redo_video`, earlier clips kept as `anim_versions`), and `run_animate` cuts every kept sticker again (when its first frame shows another grid than the batch's, `engine.grid.detect_grid` on that frame, Haitham 2026-10-15, the import answers 409 with `detected_grid`, `batch_grid` and `cells`, nothing stored, and the Studio asks; **Cut it as R×C anyway** sends it again with `grid_ok=1` and it is cut with the batch's own grid; another grid is never offered, because the batch's stickers are its cells); a **video sheet** -> attached to it (approved first when only BUILT), and when that sheet already has a video the one in use is retired (`redo_video`) and `quick_sheet` builds the next `A<n>` at the same gap; `slice_video` cuts it, G4 asks again. The answer says which sheet won (`match: {sheet, distance, distances}`, `message`). A file used before is simply cut again, every time: no duplicate check for a person's own file (Haitham, 2026-10-15: "user picks an image -> slice -> picks another video used before -> slice -> export"), so the "Already imported" dialog and the `again` flag are gone; only an explicit retry finishes the earlier batch. Job/task IDs still route a file naming a provider ticket to its failed job. Interrupted imports have durable reservations and retry their existing batch. The Studio controls and HTTP shapes are in [api.md](../api.md#import-an-existing-sheet-or-video-native-fastapi).

Manual nine-emoji batches use the same gates and templates, with saved pack-scoped duplicate decisions. `flow/gates.quick_add` enforces the plan's target before approvals and calls `Library.add_emoji_from_generation` for each kept cell. Overwrite preserves the Library sticker ID and links, saves one previous file/source for Undo, and changes no other pack. Add assigns the next numbered variant; upgrading that variant to animation can keep its ID. Delivery retries skip cells already copied from that generation. See [manual batches](../agent-and-chat.md#manual-emoji-batches) and the [JSON contract](../api.md#manual-nine-emoji-batch-preview).
