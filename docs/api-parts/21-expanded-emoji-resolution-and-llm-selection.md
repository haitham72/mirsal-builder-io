# Expanded emoji resolution and LLM selection

<sub>Part of [api.md](../api.md).</sub>

ZIP manifest v1 assets carry `bank_version`; unresolved assets also carry `resolution_reason` (`unmapped`, `ambiguous_alias`, `invalid_emoji`) and canonical token `candidates`. Both ZIP exporters persist their interpretation in `out/export_resolutions.json`; source media stays intact. Library sticker updates accept optional `action` (canonical bank token; empty string clears it); invalid choices return 400. Details: [export architecture](../export%20to%20team/mirsal-export-architecture.md).

`GET /api/llm/models` retains local model fields and adds `local`, `nararouter`, `openai` groups with `{id, model, label, provider, vision, free}`, plus `default`, `selected` and `aliases` for old Luna ids. Model ids use `provider:model`. The session settings endpoint validates `models.ai` against this catalog; clearing it restores the server default. Owner-only `POST /api/ai/backend {model}` sets a global choice; `{model:""}` clears saved local/cloud model selections. Bare ids on that global endpoint retain the legacy local-model contract, except Luna, which normalizes to `openai:gpt-5.6-luna`. New cloud defaults and new Telegram chats use `openai:gpt-6-luna` with `high` reasoning; environment overrides and saved choices retain precedence. Details: [Models](../agent-and-chat.md#models-servicesllmpy).

The Cloud dropdown shows a curated set only (Haitham's list, 2026-10-12): Nararouter offers its seven listed models and OpenAI offers `openai:gpt-6-luna` and `openai:gpt-6.1-sol`, each only when the authenticated account catalog lists it. Anything else the endpoints advertise is never offered. Bare/router Luna 6 ids normalize to `openai:gpt-6-luna`; older Luna 5.6 selections retain their version and normalize to its official OpenAI id.

Cloud catalog reads and model calls authenticate separately: official OpenAI uses `OPENAI_API_KEY`; Nararouter uses `NARAROUTER_API_KEY` with `MIRSAL_CLOUD_URL`. A missing provider key is never replaced by the other's credential. Cloud calls use their provider's endpoint; custom base-URL overrides apply only to local calls. Keys are never included in API responses.

Vision descriptions and pre-review use one Nararouter fallback attempt on failure, including failures of pinned OpenAI models. The configured fallback is `MIRSAL_LLM_FALLBACK`, authenticated with `NARAROUTER_API_KEY`; successful vision ledger entries include `fallback_from` and `fallback_reason` and record the actual answering model. This does not alter session model selections or existing API response shapes. See [vision recovery](../agent-and-chat.md#the-vision-judge-mirsalvision).

### Manual nine-emoji batch preview

`POST /api/plan` also accepts `{emojis, pack_id?, prompt?, decisions?, replacements?, style_id?, loop?}`. `emojis` is a string containing nine complete emojis or a nine-element list. `pack_id` must be owned by the caller (404 otherwise); omit it for a new pack. Decisions and replacements are objects keyed by one-based cell number, for example `{"1":"add","4":"skip"}` and `{"4":"🌈"}`. Decisions are `overwrite`, `add` or `skip`; replacements must be unused in both the pack and the proposed batch. Malformed inputs return 400 in words. This endpoint reads only the caller's Library pack, without reserving a task or calling a provider.

The response is `{entries, ready, waiting, suggestion, plan?}`. Each entry contains `{index, emoji, original, duplicate, choice, version}`. Unresolved duplicates or skipped cells have `ready:false` and no `plan`. Once resolved, `plan` is the template plan to pass to `POST /api/live/sheet {prompt, grid:"3x3", style_id?, plan}` through the usual priced confirmation. Its `slots.emoji_batch` metadata is validated against the previewed cells and saved with the generation. Ownership and new repeats are checked again before provider submission; a newly introduced duplicate returns 409 and requires another preview. Delivery (`POST /api/generations/{id}/add`) applies the saved decisions only within the planned target pack. A batch planned for a new pack may bind only to a new/empty owned pack. Source emoji changes require a new preview.
