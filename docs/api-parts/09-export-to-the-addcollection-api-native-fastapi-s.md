# Export to the AddCollection API (native FastAPI; `services/collection.py`)

<sub>Part of [api.md](../api.md).</sub>

The Mirsal Creator API's "Submit a Pack for Approval", an external emoji CMS (`docs/Api/AddCollection-API .md`): the collection goes into its approval workflow. **Export to collection** on the Library's pack page and in the Studio (one batch, beside Download .zip) sends the stickers of that Download .zip, in the same order, as ONE new collection. Owner only (like Telegram), on the owner's own packs; free, but outward, so the page always asks first (name, description, where it goes).

- `POST /api/packs/{id}/export-collection` and `POST /api/generations/{id}/export-collection` (and `/api/v1/` aliases) are **queued**: they refuse at once only what can be refused at once (not the owner, no such pack or batch, a name or description over the limits, no developer key: 403 / 404 / 400 / 503) and otherwise answer `202 {id: "X…", state: "queued", position}`; one worker sends the queued exports in order (`queued` → `preparing`, the Download .zip being built → `sending` → `done` | `failed`). `GET /api/collection/exports/{xid}` (owner, its sender only, else 404) answers the state, and once final the send's answer `{ok, status, collection, count, response, result, error?}`; each state is `out/collection_exports/<xid>.json`, and one the server was still running when it restarted reads as `failed` ("send it again"). The sender gets a notification with the outcome (kind `update`), and the dialog closes at once and the page toasts the outcome when it comes. Body `{name?, description?, retime?, light?}` (`light`, the dialog's **Quality**: false, the default, sends the files as stored, full quality; true sends the smaller re-encode, every frame kept, `library.light_webm`) (`retime`: animations shorter than 3 s are sent stretched to 3 s; the dialog offers it when there are any) (default name: the pack's, or the batch's subject; the API's limits are checked before anything is uploaded: a name over 40 or a description over 160 characters is a 400 with a sentence; an empty description is sent as the name, since the API requires one; an empty tags string is never sent). The zip's `manifest.json` is the one source: `Media` is repeated once per asset in manifest order (`.webm` animated, `.png` / `.webp` static, the export file name), `ContentSubType` (required by the CMS) is `webm` for animated stickers or a mix, else the stills' own `png` / `webp` (`collection.content_subtype`); `MediaThumbnails` is repeated once per `Media` part in the same order, a PNG named `{stem}.png` (`collection.thumbnail`: a `.png` sticker as it is, a `.webp` converted, a `.webm`'s first frame with its alpha); `MediaMetadata` is one JSON string `[{emoji_utf, tags}]` of the same length, paired by index: `emoji_utf` is the asset's first grapheme cluster, `tags` its action tokens joined by `_` (`laugh_rofl_lmao`). `Authorization: Bearer` from `MIRSAL_COLLECTION_API_CREDENTIALS` (the `sk-...` developer key from the CMS's Developer Keys page; a legacy `user:password` or its base64 still sends HTTP Basic), to `MIRSAL_COLLECTION_API_URL` (the code's default `https://emojicms.ehub.ae`; the API's own example uses `https://emojicms.devinprocess.com`) + `/api/v1/Upload/AddCollection`.
- 200 `{ok, status, collection, count, response, result, error?}`: `ok` is a 2xx whose JSON does not say `Success: false`, `result` the API's `Result` (the created pack). A refusal by the CMS is an answer (`ok: false`; `error` is its `ErrorMessages` joined by `; `, else its `message`, else an ASP.NET validation answer's title and each field's errors, else its text; a 401 says the developer key is missing, invalid or expired and how to replace it), never an exception; the refusal's body is kept in the log line. 503 when the credentials are not set (the message says what to put in `.env`), 504 when the CMS does not answer, 409 with nothing accepted, 404 for a pack or batch that is not the caller's, 403 for a member.
- `GET /api/collection` -> `{configured, url}` (never the credentials); `python -m mirsal doctor` prints the same line. Every export, ok or not, is a line in `out/collection_exports.jsonl` (who, what, the collection name, how many, the answer's status), never the credentials.
