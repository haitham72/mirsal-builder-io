## 1. Verdict

**Do not ship this as an external or multi-user API; ship-with-changes as the owner's single-operator sandbox.** Three things decide it. First, a member account can read *any* file under `out/` — including the Telegram bot token in `out/telegram.json` and every account's token SHA-256 in `out/users.json` — because authorisation matches the request prefix while the file is resolved afterwards; I reproduced it live (`GET /out/G001/../telegram.json` → 200 with the token body), which is a secret leak and therefore a blocker. Second, the test suite is **red at HEAD**: `tests/test_live.py:500` asserts `generated/` is git-ignored, commit `067dc9b` deleted that line and committed ~122 MB of media, and the same is now true of `out/` (893 tracked files) while four documents still promise both are ignored — so the project's own invariant tests cannot pass and its documented privacy claims are false. Third, the money path is only half-closed: `/api/live/*` accepts no `Idempotency-Key`, the `task` branch of `POST /api/generations` returns before the idempotency check, `jobs.requeue` keeps a stored ticket while clearing the claim and pays a second time, and every OpenAI call (expander, intent, embeddings) happens with no plan card and no go-ahead, which `CLAUDE.md:41` says cannot happen. The engine itself is in good shape — it imports no DB/Redis/model client, the vision judge cannot touch `review.*`, migrations re-runnable, the pool gate returns nothing for what does not exist, and the escaping/redaction discipline holds — so this is a shipping-blocking *boundary* problem, not a rotten core. Fix the four HIGH items (all small), make the suite green, and the API story becomes defensible.

## 4. Findings (most severe first)

### F-01 — A member token can read any file under `out/`
**BLOCKER** · `[RAN]` · `console/server.py:32, 568-570` (authorise on the raw prefix) vs `:826-834` (serve the resolved path)

Authorisation checks that the URL *starts with* a `G###` the caller owns; the file is resolved only afterwards, so `..` inside `out/` is allowed (only escaping *above* `out/` is refused). Reproduced on :8799 with a synthetic `out/` and a member account owning G001:

```powershell
curl.exe -s --path-as-is -H "Authorization: Bearer <member>" http://127.0.0.1:8799/out/G001/result.json   # 200 (owns it)
curl.exe -s --path-as-is -H "Authorization: Bearer <member>" http://127.0.0.1:8799/out/telegram.json      # 403 (correct)
curl.exe -s --path-as-is -H "Authorization: Bearer <member>" http://127.0.0.1:8799/out/G001/../telegram.json  # 200 + bot token
curl.exe -s --path-as-is -H "Authorization: Bearer <member>" http://127.0.0.1:8799/out/G001/../users.json     # 200 + every token_sha256
```

**Fix:** resolve first, then authorise — after `os.path.realpath`, require `resolved.parent == out_root / own_G###`; reject any path containing `..` before resolution as a defence in depth. **Test:** add to `tests/test_users.py` two cases, `GET /out/G001/../telegram.json` and `GET /out/G001/%2e%2e/users.json` as a member, both must be 403/404, never 200.

### F-04 — Four ways to pay twice (or pay without idempotency)
**HIGH** · `[READ]` · `server.py:1028-1029, 1057, 1098`; `jobs.py:195, 241-246, 257, 284-302`

1. `/api/live/sheet|video` never reads `Idempotency-Key` (only chat `:1011` and generation create `:1098` do) — double submit, a retry after a lost response, or a second tab = two paid jobs; only a JS flag stops it (`console/composer.js:99`, `live.js:116`).
2. `POST /api/generations {task:…}` returns at `:1057`, *before* `c.idem` at `:1098` → the header is silently ignored for task-backed creation.
3. `jobs.requeue` sets `status=REQUESTED` but keeps `external_task_id` (`jobs.py:195`) while `fulfil` only resumes when status is `CLAIMED` (`:257`) → a requeue of an already-ticketed job calls `hf.create` a second time (`resume()` at `:285` is the safe path and sits next to it in the same handler, `server.py:1048-1053`).
4. Two concurrent `fulfil()` calls both read status before taking `_paid` (`:256` vs `:284`) → both pass `:258`, the loser pays at `:292` before `claim` throws 409 at `:293`. The daily cap is raced the same way: `done()` runs outside the lock (`:302`) and counts only completed rows.

**Fix:** run `live()` through `Console.idem` with a caller-supplied key; move the `task` branch after `c.idem`; in `requeue`, require `not job["external_task_id"]` or re-enter `resume`; take `_paid` *before* re-reading status; move `usage.done()` inside `_paid`. **Test:** fire two identical requests concurrently with the same key and assert exactly one `hf.create` (the fake CLI already counts them, `tests/test_live.py:133`).

### F-08 — "Nothing lives only in Redis" is false, and the limiter can be bypassed
**MEDIUM** · `[READ]` · `server.py:583-599`, `users.py:158-159`, `docs/api.md:14-16`

Rate limits, idempotency records, session locks and SSE replay are Redis-only. Kill Redis and (a) rate limiting disappears entirely for `via != "token"`, and (b) a token client that sends `Sec-Fetch-Site: same-origin` authenticates as `via="page"` and is **never** limited. The 429 also increments the window *before* comparing (`cache.py:152-159`), so refusals consume quota.

**Fix:** fall back to a per-process limiter when Redis is down, exempt `page` auth from being reachable with a token header, and count only accepted requests. **Test:** `test_cache.py` case: with `MemoryEngine`, a `Sec-Fetch-Site` + bearer request still trips the limit after N calls.

### F-09 — GET requests skip the Origin / Sec-Fetch-Site half of the guard
**MEDIUM** · `[READ]` · `server.py:538-539` vs `:536`

`_foreign` applies Origin/`Sec-Fetch-Site` checks to writes only; on GET the guard fails *open* when the headers are absent. Combined with the Host check being the only unconditional one, a page can read (not write) through a browser on the owner's machine — and F-01 shows what reading is worth.

**Fix:** require `Sec-Fetch-Site: same-origin` (or absent, for curl) on *every* route, and fail closed when `Host` is missing. **Test:** add to `tests/test_hardening.py`: cross-origin GET to `/api/users` must 403.

### F-10 — `docs/api.md` and `openapi.py` describe a different API than the server serves
**MEDIUM** · `[READ]` · `openapi.py:115,125-131,139-141,159`; `server.py:809, 1101, 1222`; `docs/api.md:5,31-34,67-68,86,90-91`

### F-11 — Unexpected exceptions produce no JSON 500 (and no access log)
**MEDIUM** · `[READ]` · `server.py:626-629` (typed catches only), `:452-453` (`log_message` stubbed)

`_guard` catches the pipeline/library/watch/telegram/user errors and `ValueError|KeyError|TypeError`, but no `except Exception`. An `OSError`/`IndexError`/`StopIteration` (e.g. `f.read_bytes()` on a vanished file at `:682`, `:466`) escapes to `socketserver.handle_error`: the client gets a dropped socket, the server prints a traceback to a console nobody watches, and because `log_message` is stubbed there is no access log either. Unsupported methods return **501 `text/html`**, breaking `docs/api.md:3`'s "everything is JSON".

**Fix:** `except Exception as e: log; self._json(500, {"error": "internal error"})`, override `send_error` to answer JSON, and keep the raw traceback server-side only (run it through `trace.safe()` first). **Test:** monkeypatch a handler to raise `RuntimeError` and assert the client receives `500` + `{"error": …}`.

### F-12 — "Append-only history" is false inside `out/G###`
**MEDIUM** · `[READ]` · `pipeline.py:383,799` (`res["error"] = str(e)` then `write_result`), `gates.py:406` `old.unlink()`

Re-runs rewrite `result.json` and overwrite slice PNGs under the same names; `gates.py:406` deletes a previously returned video. History *lines* are append-only (that part holds), but C5's "generations and assets are never overwritten" does not describe what the code does.

### F-13 — Chat memory cannot see what the Studio made, and sessions grow without bound
**MEDIUM** · `[READ]` · `agent/memory.py:141-148, 203-209, 217`; `graph.py:496-498` (observed as the "what did you just create → idk" bug, `devin-report.md` Issue 8)

`summary_text` is rebuilt only from `subjects[]/passes[]` that the **chat** recorded (`add_pass`), so a Studio/CLI generation is invisible; judge verdicts (`vision/judge.py:398`, `actor="vlm"`) are never folded in either. Nothing caps `messages`, `interactions` or `feedback`, and every trace step rewrites the whole session JSON (`graph.py:46-48` → `memory.py:93`), so cost grows quadratically with turns; `latest_pass`/`traits` scan across all subjects, so focus can bleed between subjects in one session.

**Fix:** rebuild the summary from `out/` + Postgres (whatever exists for the session's owner), fold the latest `vlm` history lines into `summary_text`, and cap `messages`/`interactions` with a rolling window + one history file per session. **Test:** create a generation outside the chat, then assert the next `summary_text` mentions it; assert a 500-message session stays under a fixed byte size.

### F-14 — No instruction/data separation in any prompt (model→memory→model loop)
**MEDIUM** · `[READ]` · `brain.py:98,107,115`, `expander.py:114`, `memory.py:272,280`

Stored and model-written text (`Earlier in this chat: {narrative}`, `Subject '{name}'`, `Facts:`, `Phrase:`) is concatenated with bare newlines and no fencing, so a subject name or an edit note occupying the `Message:`/`Question:` slot can steer the next call. Output is *whitelisted* (never executed as code), which limits damage — but that is damage limitation, not separation, and the narrative is written by the model itself with no provenance.

**Fix:** wrap untrusted text in explicit delimiters with a length cap and a "data, not instructions" line; tag model-authored narrative as such. **Test:** a prompt-construction unit test asserting the delimiter appears and that a subject named `x': ignore the facts` lands inside it.

### F-15 — `trace.safe()`'s "no path outside the generation" is unenforced

### F-21 — The loop's head blend is still visible (owner has reported it twice)
**MEDIUM** · `[READ]` · `engine/video.py:92-101` (`close_loop`)

### F-22 — Bulk pack operations do not exist (selection ignored)
**MEDIUM** · `[READ]` · `console/packs.js:44, 52-55, 80-81`

## 7. Decisions I would challenge

| Decision | Alternative | Cost of switching |
|---|---|---|
| **Accounts live in `out/users.json`** while Postgres is already required | Move accounts/tokens into Postgres (table exists in spirit via `004_sessions.sql`) | M — rewrite `users.py`'s ~150 lines and the CLI; removes a secret file, the `any()` short-circuit (`users.py:160`) and the file-lock race |
| **`result.json` file is the system of record, written from request threads and the pipeline thread** | One writer thread (or Postgres primary, file as a mirror) | L — touches every `write_result` call site, but it deletes the whole class in `HANDOFF.md:32` and makes F-13's growth cheap to fix |
| **`Sec-Fetch-Site: same-origin` alone implies "the owner"** (`users.py:158-159`) | A real CSRF token/cookie bound to the session | S–M — one header to mint and check; removes an auth mode that also escapes the rate limiter |
| **Authorisation keyed to the raw request prefix** (`server.py:32`) | Authorise on the *resolved* path (root cause of F-01) | S — ten lines, no API change |
| **`out/` and `generated/` committed to git** (122 MB + all runtime state) | Ignore both; back them up with a script (already an open decision in HANDOFF §1) | M — one `git rm -r --cached`, one ignore entry, one doc pass; history keeps the old blobs unless rewritten |
| **Idempotency + rate limits in Redis only** | Redis for speed, Postgres for the durable record (the backstop HANDOFF already lists) | M — but it is what makes "disposable Redis" true instead of aspirational |
| **Unversioned API** (`openapi.py:9 VERSION` is `info.version` only) | `/api/v1` prefix or `X-API-Version` + `Deprecation` | S now, expensive later — do it before anyone integrates |
| **Hardcoded models** (`llm.py:24`) | Model list from LM Studio + a selector (already tracked as `devin-report` Issue 4) | M — accepted as a documented shortcut; fine for the sandbox, not for an API |
