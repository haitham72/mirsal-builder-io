# Review of Mirsal Builder  2026-10-02  c67dea1

## 1. Verdict

**Ship with changes.** The engine is solid, the golden path works end-to-end, and the security boundaries are real. The three things that decide this: (1) Python's BLOCK is genuinely final — no code path lets a human or VLM override a verifier failure except the documented `allow_animation` for `inside_slot`/`cross_slot`; (2) the agent cannot spend credits without a user go-ahead because every paid tool method checks `_may_spend()` and the graph nodes only call them after `CONFIRM`; (3) the Host/Origin guard plus per-user ownership on batches makes the local server safe for a member-token scenario. What holds it back from a clean ship: OpenAI calls that bypass the price-before-spend rule (rule 13), and one real in-process race on `result.json` between two request threads that the docs acknowledge but do not fix.

## 4. Findings

### F1 — OPENAI CALLS WITHOUT PRICE VIOLATES RULE 13
**Severity:** HIGH  
**Label:** [READ]  
**Where:** `agent/brain.py:114-118` (intent classifier, sticker picker, summariser), `services/embed.py` (pool embeddings), `generation/expander.py:54-70` (AI enhancer)  
**What:** `CLAUDE.md` rule 13 says "Paid calls (Higgsfield, OpenAI) happen only after the price is shown and the user agrees." The brain's `classify`, `pick_stickers`, and `summarise` methods call `llm.complete()` which routes to OpenAI when `MIRSAL_LLM_PROVIDER=openai` — with no price shown and no go-ahead. The embedder calls OpenAI `text-embedding-3-small` for pool vectorisation with the same bypass. These are small calls (a few cents each) but they break the rule the project explicitly enforces.  
**Reproduce:** Set `MIRSAL_LLM_PROVIDER=openai` with a real key, run any chat turn that needs classification (e.g. type "hello" when no generation exists — the AMBIGUOUS fallback hits the model).  
**Fix:** Route brain and embed calls through a separate "free tier" gate: either hardcode local-only for these paths, or add a monthly OpenAI budget cap and show cumulative spend in the settings panel. The doc itself flags this in HANDOFF.md §1 under "Decisions" — this is known.  
**Test:** A test that mocks `llm.complete` and asserts zero calls when the provider is set to openai and no explicit budget flag is passed.

### F2 — IN-PROCESS RACE ON `result.json` BETWEEN TWO REQUEST THREADS
**Severity:** MEDIUM  
**Label:** [READ]  
**Where:** `flow/pipeline.py:60` (`_IO_LOCK`), `console/server.py:78` (`self.lock`)  
**What:** `Console.lock` is acquired while a background job runs and released when it finishes. Between the release and the next request, two threads can interleave a read-modify-write on `result.json`: thread A reads, thread B reads (same snapshot), thread B writes, thread A writes (overwrites B's changes). The docs say "two request threads can still interleave inside the server" (HANDOFF.md §2). The cross-process writer lock (`writer_lock.py`) prevents two *processes* from writing simultaneously but says nothing about two threads in the same process.  
**Reproduce:** Send two `POST /api/generations/<id>/review` requests for the same batch at nearly the same time (one Approve, one Reject). The second will silently lose its decision.  
**Fix:** Hold `_IO_LOCK` around the entire read-modify-write in every endpoint that touches `result.json` — not just `_atomic_write`. Alternatively, make `review`, `drop`, `allow` acquire `_IO_LOCK` before reading.  
**Test:** `tests/test_multiprocess.py` already covers cross-process; add `tests/test_thread_safety.py` that fires two concurrent review requests and asserts the later one wins.

### F10 — `POST /api/chat/sessions/{id}/messages` DOES NOT CHECK OWNERSHIP BEFORE ACCEPTING
**Severity:** LOW  
**Label:** [READ]  
**Where:** `console/server.py:~520` (chat send route)  
**What:** The route accepts any valid session ID. `chat_parts(self.user)` loads the session store with `see_all=user.get("role") == "owner"`, so a member's `store.load(sid)` raises 404 for another member's session — but the 409 ("assistant still working") can fire before the 404 if the session exists and another member's turn is running. **Fix:** Check ownership in `_authorize` for `/api/chat/sessions/*` POST, not just in `store.load`.  
**Test:** Member A sends a message to S002 (belonging to Member B); expect 404, not 409.

## 5. What is solid (so it is protected from "cleanups")

1. **The verifier catalogue** (`engine/verify.py`, 44 checks, 9 stages) — pure numpy/OpenCV, no external deps, every threshold measured on real sheets. This is the spine. Any "simplification" that removes checks must be justified against the measurements.
2. **Ticket-first job lifecycle** (`generation/jobs.py:fulfil`) — claim before wait, resume on crash, paid-lock serialized. This is what prevents double-spending. Do not replace with a simpler fire-and-forget.
3. **Agent spending guard** (`agent/tools.py:_may_spend()` + `graph.py:n_confirm`) — the graph structure makes it impossible to reach a paid call without an explicit confirm node. Any refactoring of the graph must preserve this topology.
4. **Host/Origin + member scoping** (`console/server.py:_foreign`, `_authorize`) — the security model is real, not cosmetic. The 404-for-stranger-batch rule (never 403) is intentional and should stay.
5. **Atomic write with unique temp** (`runtime/atomic.py`) — unique temp per write (`{pid}.{thread}.{counter}.tmp`) means two processes never collide on the same `.tmp`. This is the right fix for the Windows WinError 5 problem.

## 6. Missing

**Tests:**
1. **Thread-safety of `result.json` reads during concurrent reviews** (F2) — the existing `test_multiprocess.py` covers cross-process, not intra-process.
2. **Member cannot list all jobs** (F9) — a test that creates two members, each starts a job, and asserts the other sees only their own.
3. **Pool quality gate regression** — a fixture with a known-empty pool queried for a non-existent subject must return `[]`; without it, a future threshold change could silently regress.
4. **Consent enforcement** — a test that calls `judge_generation` with `allowed=False` and asserts `ConsentRequired` is raised before any image is decoded.
5. **Idempotency across server restart** — restart the server without Redis, send the same `Idempotency-Key` twice, assert the second returns the cached answer from Postgres.

**Docs:**
1. **A one-page "what screen lives in which doc"** table. Currently a model has to open `docs/engine-and-studio.md` and grep for "Generate" or "Library" to find where a screen is described.
2. **The OpenAI cost decision** (HANDOFF.md §1, "Decisions") needs a resolution — either fold into the plan card or scope rule 13 to Higgsfield only. The current ambiguity is a walking violation.

**Features a v1 needs:**
1. **Backup command for `out/`** — the repo tracks ~900 files of real generations. There is no documented restore path if the disk fails.
2. **Arabic prompt handling** — `transformations/detect` only matches English patterns; `resolver_utterances.md` exists but the detector has not been tested against it (HANDOFF.md §2, Agent and chat).

## 7. Decisions I would challenge

1. **"The product is an API / app, screens are a sandbox"** (CLAUDE.md rule 11). This is the right call for the Mirsal app integration, but it means the Studio UI owns no business logic — all logic is in `engine/`, `flow/`, `generation/`. The risk is that a future developer adds logic to `console/` "because it's quick," creating a dual implementation. Enforce with a linter rule: `console/` may not import `psycopg`, `redis`, or define business logic beyond routing.

2. **Hardcoded local models** (`qwen3.5-4b:2`, `nomic-embed-text-v1.5`). This is a deliberate choice (no LM Studio model-list query, no dependency on a running server for core functionality). The trade-off is that switching models requires a code change. Challenge: consider a `models.json` registry in `out/` that the server reads at startup — same effect, no code change needed for model swaps.

3. **`out/` tracked in git**. 900+ files of media metadata and paths is heavy. The justification (backup + reproducibility) is real, but it means every new generation bloats the repo. Challenge: move generations to a separate LFS track or a backup script; keep only `library/`, `jobs/`, `model_calls.jsonl` in git.
