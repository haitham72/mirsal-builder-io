# 9. Three outputs, all optional (2026-10-13)

<sub>Part of [reaction.md](../reaction.md).</sub>

WebM VP9+alpha stays the primary and only Telegram delivery. Kling-animated sprites stay the paid path. **Lottie JSON** is the third, web-only output: `engine/lottie.export_lottie(p, png_or_pngs, size=512)` maps the deterministic trajectories onto **image layers** (`ty: 2`) over the real sprite, embedded once as a base64 PNG asset (`e: 1`), so a standard player (lottie-web, the LottieFiles preview) plays the picture flying. Before 2026-10-13 it emitted white ellipse placeholders, which is why players showed shapes or nothing. Each layer lives from its particle's birth to its death (`ip`/`op`) with one hold keyframe per frame for position, scale, rotation and opacity; layers are ordered biggest on top, as `simulate()` draws them. Lottie cannot turn an image's hue, so with `hue_var` > 0 each particle's hue is rounded to `HUE_STEP` (10°) and every step in use is one more tinted asset. `POST /api/particles/{id}/export-lottie` embeds the set's picked sprites (an animated sprite as its fullest frame: Lottie image layers are stills) and is a 409 when the set has none; it stores `renders/L###.lottie.json`; the burst panel's **Lottie** button downloads it. No new dependency (stdlib JSON + Pillow). Limits: 300-750 KB per file (keyframes per frame per particle, plus one PNG per hue step), renderer differences, Telegram never reads it.
