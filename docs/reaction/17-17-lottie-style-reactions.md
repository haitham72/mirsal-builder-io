# 17. Lottie style reactions (2026-10-14)

<sub>Part of [reaction.md](../reaction.md).</sub>

**The decision (Haitham, 2026-10-14):** Reaction effects has two permanent styles, chosen by the **Style: Emoji style | Lottie style** tabs at the top of `#/reactions` (kept in the browser as `rx.style`; Emoji is the default). **Emoji style** is everything in sections 13-16, unchanged. **Lottie style** ignores the emoji bank, the glyphs and the motion presets: every Lottie file dropped in `mirsal/lottie/` (`MIRSAL_LOTTIE_DIR`; the section 16 scan, so >2 MB or non-Lottie files are skipped) is one reaction, named by its file, and **every particle is a whole instance of that Lottie** (its own playhead from its birth, never a raster).

- **Screen** (`console/lottiestyle.js`): a grid of **thumbnails**, each file's own animation drawn by lottie-web, still on its middle frame and playing while pointed at (name, seconds, saved; size and fps in the tooltip); a click opens the editor on that file with the neutral start (`flow/lottie_reactions.START`: the engine defaults, burst from the centre, no swirl, no preset). The viewer is the **bundled lottie-web 5.12.2** (`console/vendor/lottie-5.12.2.min.js`, MIT, loaded only in Lottie style, no CDN) playing the export JSON itself: viewer = export, 512 x 512, 2 s, the Border checkbox kept. Sliders: Motion (Speed, Speed variation, Speed pulse, Pulse rate, Gravity, Swirl, Spread, Amount), Spin (Rotation, Flip, Flip variation), Shape (Size, Size variation, Size in / out), Fade out (start, duration, variation; section 13), Morph (Morph at, Morph variation, **Turns into (1:1) | Bursts into children**, the other files as thumbnail tiles to pick targets), Children, born at the morph (Children, Child size, Child size variation). Save keeps them; JSON downloads exactly what plays; Export all (.zip) is every file with its saved settings + `manifest.json`.
- **Engine** (`engine/particles.py`, every field off by default, every new random draw after the older ones: Emoji style output is byte-identical, a fingerprint was compared): `speed_var` (launch speed x 1 +- share), `speed_pulse` + `pulse_hz` (the displacement x 1 + amp sin(2 pi f t + seeded phase): particles swell and slow), `flip` + `flip_var` (the cheap spin: horizontal scale cos(2 pi rate t), 100% -> -100% -> 100%, applied by the raster draw and every Lottie export), `morph_at` + `morph_var` (seconds after birth, `Trajectories.morph`; `pick` chooses the target), `children` + `child_size` + `child_size_var` (Morph auxiliary, one level, **the morph starts the children** (Haitham 2026-10-14): at a root's morph (its fade start when Morph at is 0) it bursts `children` particles from where it is, same settings, its own seeded fan; `morph_burst` 0 = Turns into: the root goes on as its target; 1 = Bursts into children: the root fades out over `MORPH_XFADE` (0.15 s) and only its children go on; a child's size at birth = the parent's drawn size x `child_size` x exp(`child_size_var` x N(0,1)), clamped 0.1-3x, so most sit near 0.5x and a few reach 1x or 3x; `Trajectories.parent`; children die by 1.8 s like everyone).
- **Export** (`engine/lottie.export_lottie_burst`): ONE self-contained Lottie that embeds every source it uses once: the origin as precomp asset `L0`, each morph target as `L1`, `L2` ... (their own assets renamed `L<k>_<id>`, so two files never collide), however many particles show them. Each particle is a precomp layer (`ty: 0`) with per-frame hold keyframes (position, scale with the flip on x, rotation, opacity), `sr` = 30 / source fps (the source plays at its own speed) and ends when its source ends (no loop). A 1:1 morph is two layers on the same path: the origin fades out and the picked target fades in over `MORPH_XFADE` (0.15 s), the target's playhead starting at the morph; a bursting root has no target layer. Every child is born as a picked target (the origin when no target is picked) and never morphs again. More than `MAX_PARTICLES` (400, roots + children) is refused (400). No image or base64 is added by Mirsal (a source's own assets are kept as they are).
- **Storage + contract** (`flow/lottie_reactions.py`, native FastAPI routes in `console/app.py`, body model `LottieReactionBody`): `out/particles/lottie/library.json` `{files: {file: {settings, morph_targets, updated}}}`. `GET /api/particles/lottie-reactions` -> `{files: [section 16 metadata + saved, settings, morph_targets], start, keys, seconds, size}`; `POST /api/particles/lottie-reactions/{file}` `{settings?, morph_targets?}` saves (404 for a file not in the zone, 400 for an unknown key, a non-number or an extra body field; itself and repeats are dropped from the targets); `POST .../{file}/preview` (the same body) -> the composed Lottie for the unsaved editor values; `GET .../{file}/export.json` -> the saved one; `GET /api/particles/lottie-reactions.zip` -> `<file>` per reaction + `manifest.json {reactions: [{file, json, morph_targets, settings}], seconds, size}`. Free; nothing spends.
