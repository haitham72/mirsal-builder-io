# 14. The animation preset library (2026-10-14)

<sub>Part of [reaction.md](../reaction.md).</sub>

**The decision (Haitham, 2026-10-14):** "now it is not 1800+ emojis, it is 10-15 animation presets, grouped by each motion, with a couple of inner presets." Reaction effects (`#/reactions`, `console/reactions.js`) is a small library of emoji-free animations, and every bank emoji only *holds* one of them.

- **A preset** is a variation of one motion (burst, fountain, vortex, rain, confetti): id **`{motion}_{NN}`** (`burst_01`, `burst_02`, ...; a number is never reused after a delete), a name, and its settings (the Simulation keys and Size, Size variation, Size in/out; never Hue, never the motion, which is its group). Seeded once with 15: every motion × soft / normal / big (`EMOJI_START`, with Speed 0.5 / Amount 18 / Size 0.25 for soft and 1.0 / 40 / 0.4 for big). One file holds the library and the assignments: `out/particles/emoji/library.json` (`flow/emoji_reactions.py` `library`, `add_lib_preset`, `update_lib_preset`, `delete_lib_preset`, `assign_lib`).
- **The file**: `{motion}_{NN}.json`, a Lottie with **no picture and no base64** (Haitham: "strictly prohibited"): `engine/lottie.py` `export_lottie(p, slot=True)` writes ONE external image asset `{"id": "emoji", "w": 160, "h": 160, "u": "", "p": "emoji.png", "e": 0}` and every particle layer references it; the chat app supplies the emoji it shows (lottie-web `assetsPath` / an image provider). Particle scales are computed for a 160 px picture (`SLOT_PX`). A slot export has no hue variation (a player cannot recolour a picture it does not have), so the editor has no Hue slider and every preview is drawn with hue 0.
- **Each emoji holds a preset**: `assign[token]`, else its own motion's first variation (`burst_01` for a burst emoji), else the first preset. The wall's hover plays that preset with that emoji (the same fit preview and bottom-right origin as before; the pack screen's hover too). Select (Shift-click ranges, Select all) + **Assign**: one preset, or `random` = a random variation of each emoji's OWN motion (any preset when its motion has none). Assigning renders nothing, so it is instant for all 1800. Deleting a preset sends its emojis back to their motion's first variation.
- **The screen**: Animation presets first (one column per motion, its variations under it, each card previewed on the *sample* emoji = the last emoji clicked; Open, JSON, ×, + Variation; Export all), then the editor (one preset on the sample emoji: Save `{id}` | Save as new `{motion}` variation | JSON | Remove), then the wall (search, "Holding: any preset / burst_01 ...", Select, 120 at a time with Load more).
- **Export all** (`GET /api/particles/reaction-presets.zip`): every `{id}.json` + `manifest.json` = `{presets: [{id, motion, variation, name, file}], assign: {token: preset id} for every bank emoji, slot: {asset: "emoji", file: "emoji.png", px: 160}}`, so the chat app knows which file to play for which emoji.
- **Routes** (owner): `GET/POST /api/particles/reaction-presets`, `POST /api/particles/reaction-presets/{id}` (update), `POST .../{id}/delete`, `POST .../assign {tokens? (none = every emoji), preset_id: an id or "random"}`, `GET .../{id}.json`, `GET /api/particles/reaction-presets.zip`. The preview is still `POST /api/particles/emoji-preview` (a WebP file URL, never base64).
