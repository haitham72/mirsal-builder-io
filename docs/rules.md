## Structure

One generation engine, two interfaces on top, never collapsed into a monolithic prompt: creative intent → spec → generation → processing → validation → animation → persistence.
1. **The AI chat** — natural-language direction with memory per subject, an agent over the Studio's own functions (`docs/architecture.md`, "Chat and the agent").
2. **The Studio** — explicit controls, prompt-driven, deterministic (`docs/architecture.md`, "Studio").

## Rules

1. **Telegram sticker specs:** WEBM/VP9 + alpha (video); PNG/WEBP + transparency (static). Max 256 KB (video) / 512 KB (static), 512×512, 30 FPS, 3s max. Every sticker tagged with ≥1 emoji.
2. **Areas, not phases.** Engine → live generation (Higgsfield through its CLI; Nano Banana 2 for sheets, Kling v3.0 for animation; the video always comes from the normalised video sheet) → Postgres mirror, search, pool, photos, tracing → the agent and chat (LangGraph, Redis, local models) → the HTTP API. Five docs hold it all (table above). Open work per area is in `docs/backlog.md`; build only what you are asked.
3. **The generation engine is deterministic and independently testable** — never hide it behind conversational abstractions. The engine (`mirsal/engine/`) never imports `psycopg`, `redis`, `langgraph` or a model client (a test enforces it).
4. **Input types:** text, image, text+image, previous generation, previous stickers, event/topic, natural-language transformation.
5. **Default output:** 2×2 master (4 stickers), 2K → 512px final, transparent, 3s animation @ 30 FPS; explicit 3×3 remains configurable. Haitham changed the new-plan default on 2026-10-19 after finding 3×3 video laggy and low quality. Existing/imported grids stay authoritative.
6. **No dead stubs** — if a UI control exists, the backend is implemented; no setting that nothing reads.
7. **The trackers are trackers, not logs (Haitham, hard rule).** The tracker role belongs to `docs/waiting-for-haitham.md` and `docs/backlog.md` (`HANDOFF.md` is only a pointer plus the session state). An entry is deleted the moment it is implemented: record what exists as architecture in one of the five docs, then delete the line from the tracker in the same step (history lives in git). What stays is only what is open: unbuilt work, gates waiting for Haitham's verdict, backlog, questions. Check every change against the open items of the areas next to it.
8. **Lean dependencies + cross-platform.** Windows dev PC (macOS also supported); the venv is `mirsal/.venv` (the Anaconda base env has a broken numpy). Stdlib first for the ENGINE and the CLI. The HTTP layer may use FastAPI + pydantic + uvicorn. No CDN at runtime. Keep: the project venv, `pathlib` only, no shell-specific commands, ffmpeg from PATH or imageio-ffmpeg, anything fetched from the internet loaded once from disk, and `python -m mirsal doctor` as the single health check. (The server is FastAPI on uvicorn; `doctor` reports the web stack. Every area extends `doctor`.)
9. **Naming convention:** inputs are one folder per variant, `img-NNN-<subject>/` and `vid-NNN-<subject>/` (paired by NNN), plus optional pre-sliced clips in `vid-NNN/slices/`; **the watch-folder names are final, never rename them** (History's Remove moves a folder pair to `out/trash/` on Haitham's click and Restore puts it back under the same names). Outputs `{media}-{subject}-{action}[-{pack}]-{UTC time}-{hash}.{ext}` (`runtime/names.py`, since 2026-10-02; older batches keep their old names, never renamed) in `mirsal/out/G00N/slices/`, and the library's copies in `out/library/files/<G00N or own>/`. **Batch and job folders carry a label** (Haitham, 2026-10-04): a new batch is `out/G111-<task_slug>-<UTC time>/`, a new job `out/jobs/J058-<subject>-<kind>.json` (+ its folder); the id (`G111`, `J058`) stays the address everywhere (API, `/out/G111/...` URLs, asset keys, chat, Postgres) and `pipeline.gen_dir` / `jobs._path` find the folder by it; older bare names are never renamed. Never build `out / "G111"` by hand: go through `pipeline.gen_dir`, `pipeline.out_path` or `jobs.job_dir`. Never open media files to judge them; use validators and metrics.
10. **The golden path is the spine** (`docs/architecture.md`). request → plan with 1–5 tags + margin per cell (**G1**) → sheet → Python blocks bad cells → stills (**G2**) → video sheet from the approved stickers only (**G3**) → video → Python boundary check on every frame → animations (**G4**) → final pack (**G5**). Every change keeps it working end to end. Python's blocks are final **only where Telegram itself would reject the file** (format, size, codec, dimensions, fps, duration, audio, alpha) **or nothing was cut** (a cell with no picture). **Every other block is a judgement call and gets a visible "Use it anyway"** (Haitham, 2026-10-03: "any rejected image/video must give me an option to allow it"): a human may **allow** a still Python blocked (`blank_cell` when something was found, `foreground`, `inside_cell`, `no_spill`, `holes`; `still_override`) or an animation (`inside_slot`, `cross_slot`, `loop_seam`; `anim_override`) with an explicit recorded click (a history line, actor human) that can be taken back (`POST /api/generations/{id}/allow`, `kind` still|animation); the check stays in the report as a warning "allowed by you", every later cut keeps it (`verify.run` `waive`), and the gate then lets a person approve it normally; `engine/verify.py` (`OVERRIDABLE`, `TECHNICAL`) is the one table of which is which; a second exception, at Haitham's request of 2026-10-02: a **sheet-level layout problem** (`grid_detected`, `sheet_size`) never stops a sheet, it is cut anyway with a WARN on every sticker and each cell is judged on its own checks, a sheet with no key screen has one free click, "Cut it anyway" (`pipeline.recut`), and only a file that does not open is a hard stop; **standing rule (Haitham): never add a block a person cannot get past** — a new check is a warning with a visible "use it anyway" unless Telegram itself would reject the file: format, size, codec); **a rejection is never a dead end, and it is never a bare word**: on **every** surface that shows a rejected picture — the Studio tile, a **slice of the left image sheet** (the sheet itself is clickable, not only the cut tiles), the chat's card, and the agentic creator's message — the picture is visible, the reason is one sentence in plain words, and the override sits **right there** as a button on that picture ("Use it anyway" / "Take it back", a recorded, reversible click); each batch also carries ONE bulk control ("Use all anyway (N)" / "Take all back (N)") over whatever is allow-able now, and the chat's creator run must never end on "rejected" without that override; a rejection with no picture and no override is a **bug**, not a design; a human approves or rejects at every gate (**the vision model only pre-reviews and never approves**); rejection never deletes; a sticker keeps its original `S#` through every stage. Every decision is a `reviews` row in Postgres (searchable), problems become tickets in Postgres (`docs/architecture.md`, "Storage and search"), and a `history` line in `result.json`. Grids are 3×3 or 2×2 (user's choice); regenerating one sticker is a 1×1 through the same engine. **Hard truth:** request → external task id (written to `out/jobs/*.json` and `out/tasks/*.json` at `claim`, before waiting) → Postgres `tasks` row `{external_task_id, name_key}` → dev lookup and search. The verifier (`engine/verify.py`) runs at every stage and its BLOCK verdicts are final.
11. **Delivery (Haitham): the product is an API / app, not these screens.** Everything under `mirsal/mirsal/console/` and `mirsal/web/` is a **sandbox** that drives and demonstrates the engine. Design every feature as an **engine function + a stable JSON contract first** and the screen second; never put logic only in the browser. Edits, packs, jobs, chats and Telegram sends are addressable by id and reproducible from their stored data.
12. **Docs are five files, and they move with the code.** A change is not finished until the affected doc (table above), `README.md` (when the index changes), the trackers (`docs/waiting-for-haitham.md`, `docs/backlog.md`, when open work changes) and these rules (when a rule changes) are updated in the same step. Stale statements are deleted, not left beside the new ones. No new doc file without a reason Haitham accepts; open proposals live as one line each in `docs/backlog.md`, full text in git history.
13. **Never spend without a go-ahead.** Paid calls (Higgsfield, OpenAI) happen only after the price is shown and the user agrees (or turned "Ask before spending" off); tests never reach a real provider (`MIRSAL_NO_REAL_CLI`, fakes); creating a paid provider job is one at a time but **several jobs may be in flight at once** (`jobs.paid_parallel()`, `MIRSAL_PAID_PARALLEL`, default 3; Haitham, 2026-10-02: several sheets or effects "all at once"; the daily cap counts the jobs in flight; enabled owner/admin accounts with spending permission are exempt, determined from the persisted job user and server-side account store); every call is a line in `out/model_calls.jsonl`. The local chat model is free and is whatever the local server lists (LM Studio or vLLM at `MIRSAL_LOCAL_URL`): the person's pick in the chat, else `MIRSAL_LOCAL_MODEL` as a wish (a trailing `:N` instance suffix falls back to the base id), else the server's first chat model (`llm.resolve_local_model`); readiness is a real one-token probe (`llm.local_ready`), never just the model list. Cloud selections use the shared provider-qualified catalog (`services/llm_catalog.py`), with `openai:gpt-6-luna` as the built-in cloud default (official OpenAI only, reasoning effort always `high`; old router Luna ids normalize on use); saved picks and explicit environment settings take precedence. Official OpenAI authenticates only with `OPENAI_API_KEY`; Nararouter only with `NARAROUTER_API_KEY` at `MIRSAL_CLOUD_URL`, including vision fallback. The embedding model stays local and hardcoded (`nomic-embed-text-v1.5`). Tests never reach a real LM Studio (`MIRSAL_LLM_PROVIDER=none`; a test that needs one talks to a fake server). **Vision judge fallback order** (Haitham, 2026-10-12): configure with `MIRSAL_VISION_PROVIDER=openai` and `MIRSAL_VISION_OPENAI_MODEL=agnes-2.5-flash` (Nararouter) or `gpt-6-luna` (Luna/OpenAI). The judge tries models in this order: (1) configured cloud vision model, (2) `MIRSAL_LLM_FALLBACK` through Nararouter, (3) local LM Studio as last resort. When all are unavailable, stickers are marked "unjudged" under `FAIL_CLOSED` policy.

## Session guardrails

| | |
|---|---|
| **Do freely** | Fix real bugs with a failing-then-passing test; add engine functions, CLI commands and API routes with tests; new prompt template **versions** (add `_v4`, never edit one that was used); measurements; docs. |
| **Ask first** | Spending credits; verifier severities or thresholds; deleting an open item whose gate is unanswered; scrubbing a token from history; deleting `mirsal/web/`; anything that changes what the user sees or decides. |
| **Never** | Rename watch folders or outputs (rule 9). Loosen a verifier BLOCK or change "a human approves, Python's blocks are final". Open sticker media to judge it. Commit a token, `.env`, `opencode.json`, `mirsal/telegram-id.md`, `out/users.json`, `out/.asset_secret`. Write inside `inputs/Images_gen|videos_gen`. `git add -A` blind. Force-push. Touch ports 5433 / 5436 / 5437 or the other project's `.env` lines. Automate, restart or repoint the real-data server on :8770. |

**Locked decisions:** the product is an API / app and the screens are a sandbox (rule 11); the golden path and its gates; the issue colours (orange out of bounds, purple bad green screen, yellow bad loop, pink look or motion, blue file / Telegram limit, red dropped or blocked); out-of-bounds animations off by default with *Include anyway*; template-locked prompts (the model fills a small JSON, code lints it, the template builds the text); the local model is whatever the local server lists, readiness is a real probe, embeddings stay local and hardcoded; the agent never spends without a go-ahead unless "Ask before spending" is off; the vision model never approves.
