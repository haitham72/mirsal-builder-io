# Structural refactor (2026-10-20)

The five reviewed candidates are implemented: preview request caching, Studio
section registration, native API boundaries, Reactions polling ownership and
agent lifecycle/intent boundaries. [API layout](../api-parts/22-native-router-layout.md)
and [agent boundaries](../agent-and-chat/25-agent-code-boundaries.md) describe the
Python modules.

## Browser source layout

`console/index.html` remains the entry point; first-party scripts and styles now
live under `console/ui/`:

```text
ui/
  manifest.json
  shell/                 app and early theme bootstrap
  shared/                route lifecycle and TESTCARD
  features/
    studio/              composer, batch views, imports and recovery
    chat/                AI helpers, cards, controls and conversation state
    reactions/           presets, saved sets, Lottie and preview cache
    library/             packs, trash and Telegram controls
    editors/             still, animation and video editors
    settings/            preferences, accounts and users
    support/             Help and tickets
    home/                Home, welcome and Trending
  styles/                shared Studio, Chat and theme styles
  fonts/                 existing local font
  vendor/                existing Lottie player
```

`console/assets.py` is the allowlisted resolver. The manifest maps stable browser
names (`/ui/app.js`) to their source paths (`ui/shell/app.js`); canonical URLs
(`/ui/shell/app.js`) also work. No duplicate source copies or runtime imports.
The shared lifecycle loads before the shell, the preview cache before Reactions,
and every other script retains its previous order. Node source readers and the
action inventory use this manifest too; inventory names remain stable.
