Haitham authorized unattended coding and, once finished, comment, commit, push and sync (2026-10-04); do not request the previous review permission again. Keep one commit per phase with explicit paths and exclude secrets and runtime artifacts. (3) Public deployment and Google OAuth stay paused: keep their groundwork and held questions without starting them. ## Structure

One generation engine, two interfaces on top, never collapsed into a monolithic prompt: creative intent → spec → generation → processing → validation → animation → persistence.
1. **The AI chat** — natural-language direction with memory per subject, an agent over the Studio's own functions (`docs/agent-and-chat.md`).
2. **The Studio** — explicit controls, prompt-driven, deterministic (`docs/engine-and-studio.md`).

## Rules

1. **Telegram sticker specs:** WEBM/VP9 + alpha (video); PNG/WEBP + transparency (static). Max 256 KB (video) / 512 KB (static), 512×512, 30 FPS, 3s max. Every sticker tagged with ≥1 emoji.
2. **Areas, not phases.** Engine → live generation (Higgsfield through its CLI; Nano Banana 2 for sheets, Kling v3.0 for animation; the video always comes from the normalised video sheet) → Postgres mirror, search, pool, photos, tracing → the agent and chat (LangGraph, Redis, local models) → the HTTP API. Each has one doc in `docs/`. Open work per area is in `docs/backlog.md`; build only what you are asked.
3. **The generation engine is deterministic and independently testable** — never hide it behind conversational abstractions. The engine (`mirsal/engine/`) never imports `psycopg`, `redis`, `langgraph` or a model client (a test enforces it).
4. **Input types:** text, image, text+image, previous generation, previous stickers, event/topic, natural-language transformation.
5. **Default output:** 3×3 master (9 stickers), 2K → 512px final, transparent, 3s animation @ 30 FPS; all user-configurable.
6. **No dead stubs** — if a UI control exists, the backend is implemented; no setting that nothing reads.
7. **The trackers are trackers, not logs (Haitham, hard rule).** The tracker role belongs to `docs/waiting-for-haitham.md` and `docs/backlog.md` (`HANDOFF.md` is only a pointer plus the session state). An entry is deleted the moment it is implemented: record what exists as architecture in the area's doc in `docs/`, then delete the line from the tracker in the same step (history lives in git). What stays is only what is open: unbuilt work, gates waiting for Haitham's verdict, backlog, questions. Check every change against the open items of the areas next to it.
8. **Lean dependencies + cross-platform.** Windows dev PC (macOS also supported); the venv is `mirsal/.venv` on Windows and `mirsal/venv` on macOS (the Anaconda base env has a broken numpy). Stdlib first for the ENGINE and the CLI. The HTTP layer may use FastAPI + pydantic + uvicorn. No CDN at runtime. Keep: the project venv, `pathlib` only, no shell-specific commands, ffmpeg from PATH or imageio-ffmpeg, anything fetched from the internet loaded once from disk, and `python -m mirsal doctor` as the single health check. (The server is FastAPI on uvicorn; `doctor` reports the web stack. Every area extends `doctor`.)
9. **Naming convention:** inputs are one folder per variant, `img-NNN-<subject>/` and `vid-NNN-<subject>/` (paired by NNN), plus optional pre-sliced clips in `vid-NNN/slices/`; **the watch-folder names are final, never rename them** (History's Remove moves a folder pair to `out/trash/` on Haitham's click and Restore puts it back under the same names). Outputs `{media}-{subject}-{action}[-{pack}]-{UTC time}-{hash}.{ext}` (`runtime/names.py`, since 2026-10-02; G001-G096 keep their old `<media>-<NNN>-<task_slug>-<key>` names, never renamed) in `mirsal/out/G00N/slices/`, and the library's copies in `out/library/files/<G00N or own>/`. **Batch and job folders carry a label** (Haitham, 2026-10-04): a new batch is `out/G111-<task_slug>-<UTC time>/`, a new job `out/jobs/J058-<subject>-<kind>.json` (+ its folder); the id (`G111`, `J058`) stays the address everywhere (API, `/out/G111/...` URLs, asset keys, chat, Postgres) and `pipeline.gen_dir` / `jobs._path` find the folder by it; G001-G110 and J001-J057 keep their bare names, never renamed. Never build `out / "G111"` by hand: go through `pipeline.gen_dir`, `pipeline.out_path` or `jobs.job_dir`. Never open media files to judge them; use validators and metrics.
10. **The golden path is the spine** (`docs/engine-and-studio.md`, "The golden path"). request → plan with 1–5 tags + margin per cell (**G1**) → sheet → Python blocks bad cells → stills (**G2**) → video sheet from the approved stickers only (**G3**) → video → Python boundary check on every frame → animations (**G4**) → final pack (**G5**). Every change keeps it working end to end. Python's blocks are final **only where Telegram itself would reject the file** (format, size, codec, dimensions, fps, duration, audio, alpha) **or nothing was cut** (a cell with no picture). **Every other block is a judgement call and gets a visible "Use it anyway"** (Haitham, 2026-10-03: "any rejected image/video must give me an option to allow it"): a human may **allow** a still Python blocked (`blank_cell` when something was found, `foreground`, `inside_cell`, `no_spill`, `holes`; `still_override`) or an animation (`inside_slot`, `cross_slot`, `loop_seam`; `anim_override`) with an explicit recorded click (a history line, actor human) that can be taken back (`POST /api/generations/{id}/allow`, `kind` still|animation); the check stays in the report as a warning "allowed by you", every later cut keeps it (`verify.run` `waive`), and the gate then lets a person approve it normally; `engine/verify.py` (`OVERRIDABLE`, `TECHNICAL`) is the one table of which is which; a second exception, at Haitham's request of 2026-10-02: a **sheet-level layout problem** (`grid_detected`, `sheet_size`) never stops a sheet, it is cut anyway with a WARN on every sticker and each cell is judged on its own checks, a sheet with no key screen has one free click, "Cut it anyway" (`pipeline.recut`), and only a file that does not open is a hard stop; **standing rule (Haitham): never add a block a person cannot get past** — a new check is a warning with a visible "use it anyway" unless Telegram itself would reject the file: format, size, codec); **a rejection is never a dead end, and it is never a bare word**: on **every** surface that shows a rejected picture — the Studio tile, a **slice of the left image sheet** (the sheet itself is clickable, not only the cut tiles), the chat's card, and the agentic creator's message — the picture is visible, the reason is one sentence in plain words, and the override sits **right there** as a button on that picture ("Use it anyway" / "Take it back", a recorded, reversible click); each batch also carries ONE bulk control ("Use all anyway (N)" / "Take all back (N)") over whatever is allow-able now, and the chat's creator run must never end on "rejected" without that override; a rejection with no picture and no override is a **bug**, not a design; a human approves or rejects at every gate (**the vision model only pre-reviews and never approves**); rejection never deletes; a sticker keeps its original `S#` through every stage. Every decision is a `reviews` row in Postgres (searchable), (LangSmith is retired, 2026-10-04: problems become tickets in Postgres, `docs/store-and-search.md` "Tickets"), and a `history` line in `result.json`. Grids are 3×3 or 2×2 (user's choice); regenerating one sticker is a 1×1 through the same engine. **Hard truth:** request → external task id (written to `out/jobs/*.json` and `out/tasks/*.json` at `claim`, before waiting) → Postgres `tasks` row `{external_task_id, name_key}` → dev lookup and search. The verifier (`engine/verify.py`) runs at every stage and its BLOCK verdicts are final.
11. **Delivery (Haitham): the product is an API / app, not these screens.** Everything under `mirsal/mirsal/console/` and `mirsal/web/` is a **sandbox** that drives and demonstrates the engine. Design every feature as an **engine function + a stable JSON contract first** and the screen second; never put logic only in the browser. Edits, packs, jobs, chats and Telegram sends are addressable by id and reproducible from their stored data.
12. **Docs are part of every change.** A new feature area, a changed contract or a change of provider is not finished until its doc in `docs/`, `README.md` (when the index changes), the trackers (`docs/waiting-for-haitham.md`, `docs/backlog.md`) and these rules are updated in the same step. Stale statements are deleted, not left beside the new ones.
13. **Never spend without a go-ahead.** Paid calls (Higgsfield, OpenAI) happen only after the price is shown and the user agrees (or turned "Ask before spending" off); tests never reach a real provider (`MIRSAL_NO_REAL_CLI`, fakes); creating a paid provider job is one at a time but **several jobs may be in flight at once** (`jobs.paid_parallel()`, `MIRSAL_PAID_PARALLEL`, default 3; Haitham, 2026-10-02: several sheets or effects "all at once"; the daily cap counts the jobs in flight); every call is a line in `out/model_calls.jsonl`. The local chat model is free and is whatever the local server lists (LM Studio or vLLM at `MIRSAL_LOCAL_URL`): the person's pick in the chat, else `MIRSAL_LOCAL_MODEL` as a wish (a trailing `:N` instance suffix falls back to the base id), else the server's first chat model (`llm.resolve_local_model`); readiness is a real one-token probe (`llm.local_ready`), never just the model list. The embedding model stays local and hardcoded (`nomic-embed-text-v1.5`). Tests never reach a real LM Studio (`MIRSAL_LLM_PROVIDER=none`; a test that needs one talks to a fake server).
